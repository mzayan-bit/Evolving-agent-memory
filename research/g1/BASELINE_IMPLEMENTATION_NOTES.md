# Baseline implementation notes — engineering v1

Implemented 2026-09-25 under the subsequent research-engineering authorization. The earlier interface-only prohibition is superseded for **baseline infrastructure only**. Research claims, annotation thresholds and pilot gates remain unchanged. These are deterministic protocol-level analogues, not reproductions of the audited papers. No real inference or pilot has run.

All arms receive immutable `PolicyView` projections, identical explicit source evidence/rules, observed lineage, the same access configuration and resource ceilings. No arm receives affected/valid masks or expected probe answers. Optional gold-dependency/fault switches label a separate oracle run. Fixture recorded rules are explicit domain evidence independently available to every arm; they are not a hidden semantic inference service. Main natural-language data will need a separately reviewed evidence adapter.

Finite closed-rule fixture implementation; semantic rederivation adapter is deferred. |

All eight have **no oracle information by default**. Changing an access flag does not make a paper-faithful reproduction. Clean fixture lineage is an authored, complete engineering proposal; it cannot be advertised as learned perfect lineage or naturalistic inference quality. Provenance-only status-preserving retention is not counted as a content repair.

B2/B6 know only explicit rule evidence, not gold support assessments. They can therefore recover correct fixture outcomes even when the separately observed proposal is corrupted. This is a declared advantage of explicit-rule fixtures, not evidence that natural-language verification is free or reliable. The rules, underlying evidence, and resource ceilings are identical across policy arms. B5/B7 accept the same interchangeable inference provider, enabling later inference × decision-policy experiments without conflating their interfaces.

The common reader is a deterministic identity lookup with used-item IDs. It cannot generate new persistent content or silently repair the store. Retrospective historical queries apply observed corrections to archived rule evidence; historical-as-known-then queries preserve the original snapshot. No paid APIs, learned estimator, calibrated score, or uncertainty-aware policy exists in this implementation.

## Fidelity phase update — 2026-09-25

[Round-2 audit](BASELINE_FIDELITY_AUDIT.md) supersedes any interpretation of these analogues as paper-faithful competitors. B8 `CachedReplay` is now an explicitly internal (`faithful_to_original=false`) baseline with ancestor-slice cache keys, atomic cache/state commits and hit/miss accounting. It is selectable as policy `B8` in the fixture configuration, but not silently added to the old default B0–B7 suite. Original fixture expectations remain unchanged. Target-interval grounding and present-permission historical disclosure bugs were fixed. Natural-language fidelity and actual provider budget enforcement remain R0 study gates.
