# Baseline expectations — conceptual, not executed

Every statement below is a hypothesis from the declared policy semantics. No success rates, model outputs or reproduction scores are inferred from these drafts. Behavior of an LLM verifier or inferred graph remains unknown until run. Same underlying source history and permitted evidence must be available to all arms.

| Baseline | Expected stale errors | Expected false invalidation | Cost and where it can dominate |
|---|---|---|---|
| No repair | Old C/D can remain reusable after changes; answers might still recover from fresh evidence, so state survival is not guaranteed answer failure | No direct deletion; can still ignore valid information at readout | Cheapest maintenance; can win when retrieval always supplies authoritative current state and persistence adds no value |
| Source-only invalidation | Removes changed source version but leaves summaries/derived records | Few descendant false invalidations, but can remove still-useful historical source if deletion is destructive | Strong if no meaningful descendants or queries directly inspect sources |
| Full reset / full replay with archive | Correct replay from full permitted history should eliminate stale derivations; stochastic reasoning and unavailable sources can still fail | Should preserve justified state if reconstruction and archival semantics are correct; reset-without-archive is a deliberately different, weaker comparator | Potentially high tokens/latency; may dominate on short histories and cheap source access |
| Exact explicit-edge closure | Misses omitted paths; explicit reachability itself is exact only for recorded graph | Spurious edges and naive all-descendant invalidation harm valid alternatives | Cheap graph operations; strong with accurate conjunctive runtime dependencies |
| Broad semantic-neighbor invalidation | Can catch implicit unlogged relations but miss distant semantic dependencies | Likely collateral damage to same-topic scopes/bystanders | Retrieval/embedding plus reconstruction cost; could be sufficient when affected state is naturally localized |
| Point-estimate inferred graph | Depends on inference recall/type accuracy; mistakes can propagate | Alternative support and shared origins fail if reduced to naive parent edges | Inference cost must count; may already match a probabilistic policy if posterior decisions are sharp |
| Conservative reverify/replay | Can avoid stale reuse by checking all candidates or withholding action; miss/cap/unavailable-source errors remain | Excess quarantine and task refusal can hide valid-state loss unless measured | Strongest practical threat when checks/replay are cheap; charge every check and report task completion |
| Additional required classical baseline: point support-set TMS/rederive | Correctly retracts unsupported derivations given correct finite justifications; missing alternatives/false justifications still hurt | Preserves a valid independent alternative; false inferred AND/OR semantics still fail | May erase the entire proposed method gap without learning uncertainty; rederivation cost and inference cost count |

## What these predictions do not prove

Some C/D claims are intentionally unsupported initially (especially G1-07–12, 15, 19, 28–30). They test spurious support and ambiguity, not stale-descendant propagation from a formerly valid belief. Keep their denominators separate. Do not choose only cases where closure fails; include accurate-lineage controls and histories where full replay/requery is cheap. G1-14/17/24 are direct tests of classical alternative supports; if a support-set baseline solves them, that confirms prior art rather than G1 novelty.

Persistence can only be justified by delayed reuse or lower total future-query cost than a response-only audit/fence. A hypothetical policy that never answers is not an improvement: coverage, action completion, valid-item quarantine and historical accuracy are mandatory.
