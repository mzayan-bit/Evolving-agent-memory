# Classical prior art: much of the method story is already old

This targeted audit uses primary publisher/author material, not modern LLM terminology as evidence of novelty. The SIGMOD primary PDF was also checked at pp.157–158 and its counting/DRed section pointers. Full PDFs were inspected for ATMS (including environment/label semantics and retractable justifications), provenance semirings, probabilistic databases, factor graphs, build systems and selected portions of Acar's thesis; publisher/author records establish the TMS, AGM and dependency-backtracking entries. No historical algorithm was implemented here.

## Representation decision

Use **versioned support sets** as an annotation language first, not a mandated architecture. Each set is one sufficient conjunction; alternatives are separate sets. A bipartite graph with justification nodes or a hypergraph encodes this faithfully. A plain unlabeled pairwise graph with “invalidate every descendant” cannot distinguish `{A,B}` from `{A},{B}`. A suitably typed/labeled graph can: the limitation is semantics, not the word graph.

A DAG is convenient after version expansion but is not guaranteed: mutually reinforcing summaries and recursive rules create cycles. Unsupported self-support cycles must not create evidence. Fixed-point semantics or explicit base assumptions are required. Probabilistic support sets/factor graphs are candidates only after specifying random variables, shared sources and calibration data; an LLM confidence number on each arc is insufficient.

## Concrete classical counterexample

Let claim C have supports `{{A,B},{D}}`. A is retracted; B and D remain valid and D is independent. Naive descendant closure invalidates C. ATMS-style environments or Boolean provenance preserve C via D. No new LLM algorithm is needed for that result. If D is a copy of A, the expanded provenance is `A*B + A`; retracting A removes every justification. Resolving whether D is independent from ambiguous text is the potential empirical difficulty.

## Required baseline consequence

Compare point-estimate **support-set** truth maintenance / rederive, not only a deliberately weak point graph. Give it the same inferred relations and evidence as any future probabilistic policy. Add full replay, source requery and query-time auditing. If these classical/simple policies cover the observed frontier, stop method development.

## What could remain specifically interesting

Language-derived support is defeasible and incomplete; source authority, time and permission scopes can change; a fact may remain true but unusable; uncertainty includes unknown missing justifications. An empirical study can quantify which classical assumptions break, whether they can be annotated, and whether the break matters under matched resources. It does not invent truth maintenance, alternative supports, probabilistic inference, cache invalidation or selective recomputation.
