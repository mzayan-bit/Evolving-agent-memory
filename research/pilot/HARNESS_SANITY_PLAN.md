# Harness sanity plan — not executed, no paid inference

Five engineering fixtures below are specifications, not new benchmark observations or paper results. Implement/run them only in a later authorized engineering step with deterministic stub model/verifier responses and an in-memory simulated store. Do not invoke Claude, Qwen or any provider. Do not use their outcomes as empirical support for G1. They are not additions to the 30 annotation cases or the 12 planned held-out pilot cases.

| Fixture | Events / intended harness assertion | Failure detected |
|---|---|---|
| E1 alternative versus copied support | At t0 belief b has `{s1}` OR `{s2}`. t1 withdraws s1; with independent s2, b remains usable. A paired fixture changes s2 to a copy of s1; b cannot survive solely by double-counting the copy. An unrelated u remains unchanged. Stub verifier returns fixture-defined evidence, not learned predictions. | AND/OR collapse, duplicate-source inflation, false invalidation |
| E2 conjunctive support with missing observed member | At t0 b requires `{s1,s2}`; withdraw s1. Hidden evaluator gold stays complete; visible test graph omits s1 incidence. Graph closure can miss b, while evaluator flags stale reuse. Also run complete observed graph. No hidden affected label enters policy inputs. | Omission handling, oracle leakage, invalid expectation that every policy must succeed |
| E3 spurious relation and scope bystander | Production and staging beliefs have separate source flags. Inject a false production→staging incidence only into visible graph. Change production flag. Score inappropriate staging inactivation separately from correct production repair; do not label staging false merely because a policy deleted it. | Spurious propagation, scope confusion, metric denominator manipulation |
| E4 repeated revision, history and delayed reuse | Canonical value 4→8→4; keep a copied cache at 4 during the middle interval. After the first change, stub a summary write/retrieval using that cache and verify stale recurrence detection. At the final legitimate return to 4, do not count recurrence. Query as-known-then and historical truth after a retroactive correction in a separately labeled subfixture. | Temporal leakage, archive destruction, recurrence versus reinstatement, truth versus belief conflation |
| E5 exact ledger and cap | Stub operation manifest: verifier request input 100/output 20/cached-input 40; replay step contains two physical requests 50/10 and 30/5. Expect three model calls, one verifier call (subset), one replay step, input 180, output 35, cached subset 40, plus explicitly logged retrieval/embedding operations. With cap two credits, the third request must not start. Add a failed request/retry and missing-usage response; failures count, missing usage stays unknown. | Double billing, hidden replay calls, retry omission, cap overrun, estimated tokens misrepresented as measured |

## Planned procedure

Freeze fixture inputs, stub outputs and expected assertions before invoking any future harness. Serialize PolicyView and assert no evaluator gold, future timestamps, corruption masks, original case IDs or intended affected sets occur. Hash identical paired inputs; ensure changing a policy does not change source/probe access. Check archive version immutability and deterministic ordering. Run common scorer on deliberately wrong as well as correct states to ensure a baseline failure is measurable rather than patched away.

For E1–E4, verify exact current/historical state and use/action traces; for E5, inspect every operation rather than only aggregate totals. Report real wall time if executed, no fictional provider latency/pricing. Any fixture-derived test tokens are synthetic counts, not measured model usage. Separate engineering traces from future experimental directories and label them ENGINEERING_ONLY_STUBS.

Pass criterion: all stated interface, leakage, denominator and accounting assertions pass; expected weak-baseline failures are scored correctly. This does not validate a model, infer support, establish annotation agreement, or authorize the 384-run pilot. None of these fixtures was executed in the current preparation phase; only agreement-analysis unit tests with dummy labels ran.
