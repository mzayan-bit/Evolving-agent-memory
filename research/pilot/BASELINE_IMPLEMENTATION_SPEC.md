# Baseline implementation specification v1.0 — interfaces only

No baseline or proposed uncertainty method is implemented by this document. No model runs are authorized. Human annotation reliability is the immediate gate. This translates the [Stage-0 pilot](../g1/PILOT_DESIGN.md) into an engineering contract; proposed engineering resolutions below must be frozen before future execution.

## Separation of modules and access

The runner owns chronology and budget. The policy sees only `PolicyView`; evaluator-only gold, future events, corruption masks, source benchmark identifiers, author labels and target affected sets are separate data stores, never fields in that view. Do not serialize them and ask the model to ignore them. Every history accessor takes a checkpoint and rejects future records. All policies use the same reader, tokenizer/context window, answer prompt and query schedule. The reader cannot silently repair persistent state. Write operations go through the policy/state interface and are logged.

## Interface signatures to implement only after approval

- `reveal(checkpoint) -> list[EvidenceEvent]`: returns exactly that prefix; no gold input.
- `snapshot(checkpoint) -> PersistentState`; `history(as_of, known_at, permissions) -> HistoricalView`.
- `on_revision(PolicyView) -> PolicyResult`: a policy cannot call a provider directly; it requests runner-mediated operations.
- `execute_operation(OperationRequest, Budget) -> OperationResult + CostEvent`: common verifier/model/retrieval service, no direct gold lookup. Reserve capacity before issuing calls and stop at cap.
- `apply_mutations(expected_version, mutation_list) -> new_state_version`: append-only archive; permission revocation can block current use without rewriting factual history.
- `answer(Query, PolicyView) -> AnswerTrace`: shared reader for all eight arms; named relied-on IDs plus text for auditing implicit reliance.
- `score(EvaluatorGold, StateTrace, AnswerTrace, CostLedger) -> Metrics`: scoring reads both hidden gold and traces but never sends gold back to runtime.

## Lineage corruption

An evaluator-owned `CorruptionManifest` holds clean justification-member incidences, seed, removed incidences, inserted false incidences and origin manipulations. Main visible regimes: complete proposal versus combined target .70 true-incidence retention and .30 inserted-false/true incidence. Exact achieved rates are reported on small graphs. Sampling is deterministic without replacement and published after runs; round retained/inserted counts to nearest integer with ties upward, minimum zero. A zero-true-incidence case cannot carry a meaningful relative corruption rate and is a separate stratum.

Delete references, not evidence text. Keep rule/group identity when a member disappears; do not silently turn an incomplete conjunction into known complete sufficiency. If the policy cannot observe incompleteness, it receives the ordinary resulting point estimate, not a gold warning. Insert only evaluator-confirmed false incidences; genuinely unknown relationships cannot be used as known false positives. Independent/copy origin variants are separately labeled interventions and held identical across policies within a comparison. Clean proposal is an oracle-lineage condition if supplied from gold: report that explicitly; main end-to-end inference cannot be called 100% complete merely because no artificial corruption was added.

## Eight baseline policies

All receive the same PolicyView and may access the same past evidence pool under context/retrieval caps. The table specifies operations they actually use. No arm receives gold affected scope. Graph propagation refers to the visible relation structure, not truth guaranteed by the evaluator. The fixed reader is common and its costs are separately counted.

| Policy | Inputs used | LLM / verifier calls allowed in repair | Mutations and exact decision rule | Accounting |
|---|---|---|---|---|
| 1 No repair | Revealed events recorded in shared event log; existing state | Zero / zero | No belief mutations; reader may see new evidence through identical retrieval, but cannot persist repairs | Charge common construction, retrieval and answers; no fictional repair savings credited beyond zero operations |
| 2 Source-only invalidation | Changed-source cue, direct base records, explicit observed validity/scope | Zero / zero | Mark replaced/revoked source version unavailable for current use within stated scope. Leave derived beliefs untouched; unknown revision semantics mark source unresolved, not universally false | Charge deterministic operations and normal reading; no descendant verification hidden in reader |
| 3 Full reset / full replay with archive | Entire permitted past history and original construction routine | Replay uses common model, capped; no extra verifier outside cap | Rebuild active derived state from chronological prefix, retain immutable archives. Do not use future observations or gold to reconstruct. If incomplete under cap, keep last fully committed coherent snapshot and report budget exhaustion; no partial state presented as a successful full replay | Every reconstruction call, token, retrieval and replay step; report completed versus truncated replay separately |
| 4 Exact explicit-edge closure | Recorded visible adjacency and changed-source IDs | Zero / zero | Traverse all recorded descendants; inactivate affected current source/derived versions in scope. “Exact” means exact traversal of observed graph, not complete real lineage. No alternative-support rescue in this graph-only baseline | Graph work logged; same history retained; no uncharged semantic scope inference |
| 5 Broad semantic-neighbor invalidation | Changed source text and active belief text | Zero generative / zero verifier; frozen embedding encoder allowed | Invalidate current beliefs whose cosine similarity to the changed-source text reaches fixed threshold .70; one-hop, no gold-tuned expansion. | 6 Point-estimate inferred dependency graph | Shared frozen inferred support proposal converted to pairwise edges | No additional inference in policy-isolation arm; end-to-end extraction calls allowed only within common cap | Collapse each proposed justification to parent→target arcs; then apply closure as in policy 4. No probabilities, no alternative grouping. This deliberately differs from policy 8; it is not the only serious comparator | Shared inference charge equal across arms; actual end-to-end inference charged when that track is run |
| 7 Conservative reverify/replay | All active beliefs plus same past source pool | Common verifier per checked belief; rederive/replay calls permitted within remaining cap | Visit current claims in fixed lexicographic ID order (not gold suspicion). Verify against available evidence. Supported→retain; unsupported/contradicted→inactivate or rederive if evidence permits; unresolved→quarantine. Unchecked items are marked unchecked, not silently certified or deleted. Record inability to finish under cap | All verification/replay/retrieval charged, including checks that retain state and failures; valid-item quarantine and task coverage reported |
| 8 Point support-set TMS/rederive | Same inferred proposal as policy 6, preserving AND/OR groups and observed origins | Deterministic propagation first; common verifier/rederivation calls only for unresolved affected justifications, within cap, ID order | Remove inapplicable source-version justifications; retain target if another currently admissible sufficient set remains; otherwise quarantine/rederive or inactivate when unsupported under the stated closed rules. Copies expand to observed shared origin; no invented independence. Unsupported cycles cannot justify themselves without base evidence | Shared inference plus any checks/rederivation; no uncertainty classifier/controller, no gold rule completion |

Policy 8 must not assume semantic sufficiency can be determined purely from an updated text string. If version change invalidates a justification but updated content might support the same claim, it needs the same budgeted verifier/rederivation as other policies. Cyclic/recursive cases require declared finite grounded fixed-point semantics; unsupported cycles remain unresolved. No probability estimation or training is included.

## Cost and resource contract

Stage-0 reference is six repair credits per three-revision trajectory, initially two released per revision with unused credits carried forward. Each actual model invocation in verification, inference or replay consumes one credit; replay-step counts are separately logged. Multiple calls inside a replay step cannot count as one credit. Construction/common reader calls are logged separately; shared setup charged identically. Future end-to-end extraction must be counted, not silently provided free to one arm.

Before any future run, freeze integer total/per-call input and output token caps, retrieval cap, retry cap, timeout, model snapshots, tokenizer, embedding hash, device, context truncation rule and monetary ceiling. These values are **unset and execution-blocking now**; the interface rejects a RunManifest with missing limits. Six credits alone does not imply equal compute. Enforce independent token/retrieval ceilings. A preflight estimate reserves worst-case output capacity; reconcile provider-reported actual usage. Missing usage remains UNKNOWN, not zero. Record discrepancies between tokenizer estimates and provider usage. Never claim exact vendor billing from local token estimation.

Every physical request has a unique operation ID; retries get new IDs and preserve parent link. Count physical model calls once; verifier_calls is a subset flag, not an extra billable model call added twice. Cached input tokens are a subset of input tokens unless the provider schema states otherwise. Aggregate input/output/cached categories using that recorded schema. Pure deterministic replay with no model call consumes a replay step, zero model credits, and actual runtime; no fake token count.

Unrestricted arm still logs all resources; matched arm stops before exceeding a cap and reports unfinished work. Paired comparison uses the same backbone/snapshot, history, source access, query schedule and corruption mask. Extra evidence realization versus shared realized evidence are distinct declared experiments. Gold diagnosis and oracle support are separate upper bounds, never mixed with deployable policies.

## Leakage and execution gate

The planned 384 trajectories are 12 NEW scenarios × eight policies × two backbones × two regimes × one paired seed. Existing 30 annotation drafts are not held-out pilot data. Do not start baseline implementation or inference from this specification. Required gate artifacts: human agreement report and qualitative review, adjudicated/versioned visible evidence, approved RunManifest/cost cap, leak-check evidence and engineering sanity sign-off. This task prepares documentation only.
