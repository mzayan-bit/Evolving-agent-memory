# Adjudication protocol — prepared, not executed

1. Before annotation, coordinator approves proposed wording, hashes the exact stage packets/guide/plan, verifies participants have not read author material, and records any residual blinding failure. Distribute only one stage at a time and preserve input files.
2. Receive A/B stage submissions separately. Store immutable timestamped copies plus SHA-256; never overwrite or normalize them in place. Lock both submissions before releasing the next stage. If a participant saw later stages, log the breach and keep those data separate from a blinded reliability claim.
3. After all stages, concatenate copies into completed master files in release order. Validate fixed columns and missing/invalid labels. Ask each annotator only to resolve syntax/omissions without revealing the other’s labels. Preserve original and corrected versions with a change log; do not pressure a label change.
4. Run the frozen agreement script on the raw completed masters. Lock that report before adjudication. Numeric metrics are pre-adjudication; adjudicated agreement is not a reliability estimate.
5. Use ADJUDICATION_TEMPLATE.csv, one row per disputed unit. Copy exact A/B raw values, unit identity, disagreement category, evidence prefix, adjudicated result, rationale, adjudicator/time/protocol version and input hashes. The template is intentionally header-only now.
6. Categories: relation discovery, association/dependency, copied/independent, necessary/alternative, AND/OR grouping, time/scope, current/historical, authority/permission, action choice, ambiguity, missing premise, syntax or other. Multiple categories may be recorded as JSON. Do not infer that every disagreement means one person is wrong.
7. A third human should adjudicate using the same visible prefix, blind to authored labels and preferred method. If unavailable, moderated A/B consensus is permitted only with that limitation disclosed. Outcomes may include unresolved/ambiguous or case-needs-revision. Record both interpretations and the evidence needed to distinguish them.
8. Consult preserved author labels only after human adjudication is locked, as a separately reported author–human comparison. They are not a tie-breaker. Proposed scenario edits require new version IDs and fresh annotation; original human labels remain attached to the original presentation.
9. Apply quantitative gates and qualitative vetoes before authorizing a baseline pilot. No method/pilot is authorized by this package. Keep unresolvable ambiguity in the released record rather than deleting inconvenient cases.

The coordinator-only folder, blinding audit, mapping, source cases, agreement hypotheses and baseline design are excluded from participant packets. The entire repository is public research material, so blinding is procedural, not cryptographic; disclose any prior exposure. No annotation, adjudication or gate decision has been performed here.
