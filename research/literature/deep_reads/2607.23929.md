# Citation

**MemTX: Transactional Belief Commit for Stateful Agent Memory**. Li, Xiaoyang; Wang, Yiqi; Lu, Haohui; Chen, Zhi; Li, Mo; Song, Pingan; Zheng, Mingkai; Cai, Taotao. First public: 2026-07-27; arXiv preprint; no publication venue independently verified. [Reviewed primary version](https://arxiv.org/abs/2607.23929v2); v2 (2026-07-28).

Evidence level: targeted deep reading of method, evaluation and relevant limitations/appendices; no independent experimental reproduction. Author reports are distinguished below from reviewer inferences.

## Research Problem

Govern memory state changes and downstream actions

## Why This Paper Exists

The design targets a concrete weakness in how prior agents evaluate or use memory. Govern memory state changes and downstream actions. Its scope matters because guarantees depend on declared provenance and policy assumptions.

## Method

Treat memory updates as transactions over typed provenance, permissions, validity and confidence. Eight states distinguish raw, tentative, validated, committed, action-safe, quarantined, superseded and revoked records. Gates and cascades regulate downstream use.

## Memory Lifecycle Covered

- **Write:** Stage proposed writes
- **Retrieve:** Policy-governed reads
- **Update:** Transactional commits and conflict rules
- **Consolidate:** Governed derived memories
- **Invalidate:** Typed revocation cascade
- **Forget:** Quarantine/revocation; compensating actions where possible

## Representation

Typed provenance DAG and eight states

## Controller / Decision Policy

Transactional commit, revocation and action gates. Appendix reports a single 48GB L40 setup; API/backbone choices vary. No large pretraining needed.

## Datasets

90 cases (60 traps, 30 controls), plus a 56-case harder extension; many tasks only 1–4 turns and 1–3 agents.

## Baselines

Eight memory/governance baselines across five backbones, including Cordon plus revocation.

## Metrics

Harm, valid completion, state-policy violations and formal state-space checks.

## Main Findings

Explicit lifecycle states and dependency-aware revocation are already central contributions. Approximately 5.5 million checked machine states support the modeled contract, not arbitrary natural-language correctness.

## Ablations

Isolation, commit/gate and cascade controls; stronger scripted versus weaker LLM action paths.

## What It Actually Solves

Govern memory state changes and downstream actions. The empirical support is restricted to the tasks and controls described above.

## What It Does NOT Solve

Guarantees depend on declared provenance and policy assumptions. This is a scope assessment, not a claim that the approach could never be extended.

## Author-Stated Limitations

Static reversibility/compensation and short controlled tasks bound the recovery setting.

## Additional Limitations We Observe

Conflict detection uses structured assumptions; the action-safe existential gate is not action-specific proof. Complete recorded provenance is crucial. MemTX does not lead task success on GPT-5.5 in the main table (0.756 versus 0.778 for Cordon + revocation), so superiority is not uniform.
