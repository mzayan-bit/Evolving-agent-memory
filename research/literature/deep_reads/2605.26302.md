**Your Agents Are Aging Too: Agent Lifespan Engineering for Deployed Systems**. Zhu, Jianing; Ro, Yeonju; Robertson, John; Wang, Kevin; Li, Junbo; Vikalo, Haris; Akella, Aditya; Wang, Zhangyang. ## Research Problem

Measure degradation and maintenance across agent lifespan

## Why This Paper Exists

The design targets a concrete weakness in how prior agents evaluate or use memory. Measure degradation and maintenance across agent lifespan. Its scope matters because oracle ladders diagnose stages but need care about interactions.

## Method

Model agent lifespan through controlled compression, interference, revision and maintenance. Temporal dependency tasks expose degradation; oracle retrieval and oracle-store interventions diagnose where information was lost.

## Memory Lifecycle Covered

- **Write:** State accumulation
- **Retrieve:** Oracle retrieval diagnostics
- **Update:** Versioned revisions
- **Consolidate:** Repeated compression
- **Invalidate:** Dependency/version probes
- **Forget:** Forgetting and bystander-preservation probes

## Representation

Temporal version/dependency tasks

## Controller / Decision Policy

Oracle intervention ladder and maintenance controls. Long repeated-session sweeps are expensive; a smaller factorial pilot is feasible without training.

## Datasets

AgingBench: seven scenarios, 8–200 sessions, 14 models and over 400 runs in the reported study.

## Baselines

Agent memory configurations, typed-state maintenance and threshold controllers.

## Metrics

Accuracy over age, half-life/slope/hazard proxies, version/forget/dependency scores and wall time.

## Main Findings

Long-horizon dynamic memory and stage interventions are already studied. Typed state reduces accumulator errors in reported settings; maintenance gains depend on trigger and workload.

## Ablations

Oracle ladder; typed-state variants; threshold maintenance (Appendix D).

## What It Actually Solves

Measure degradation and maintenance across agent lifespan. The empirical support is restricted to the tasks and controls described above.

## What It Does NOT Solve

Oracle ladders diagnose stages but need care about interactions. This is a scope assessment, not a claim that the approach could never be extended.

## Author-Stated Limitations

Production external validity and controlled scenario assumptions are discussed in Appendix I.

## Additional Limitations We Observe

An ordered oracle ladder can reveal a bottleneck without uniquely assigning causal responsibility when stages interact. Artificial age and session count are not interchangeable with elapsed deployment time.
