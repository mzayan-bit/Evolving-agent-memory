# Citation

**Can Agent Memory Systems Track Evolving State?**. Fan, Xinyi; Liu, Miri; Yang, Ruozhen; Ouyang, Siru; Han, Jiawei. First public: 2026-08-20; arXiv preprint; no publication venue independently verified. [Reviewed primary version](https://arxiv.org/abs/2608.19652v1); v1 (2026-08-20).

Evidence level: targeted deep reading of method, evaluation and relevant limitations/appendices; no independent experimental reproduction. Author reports are distinguished below from reviewer inferences.

## Research Problem

Track evolving current state and dependent constraints

## Why This Paper Exists

The design targets a concrete weakness in how prior agents evaluate or use memory. Track evolving current state and dependent constraints. Its scope matters because dependency links are explicit; synthetic construction favors typed state.

## Method

Extract state units with sources, hard/soft constraints and typed derived/coupled dependencies. Superseded units remain inactive; changed prerequisites set dependent units to needs-recheck, with answer-time recomputation.

## Memory Lifecycle Covered

- **Write:** Per-turn state extraction
- **Retrieve:** Retrieve current units plus context
- **Update:** Supersession and constraint updates
- **Consolidate:** Structured state maintenance
- **Invalidate:** Dependency-driven needs-recheck flags
- **Forget:** Suppress superseded units; retain historical state

## Representation

State units with supersession and dependencies

## Controller / Decision Policy

Structured write/update and needs-recheck flags. Approximately 165–600 small-model encoder calls per scenario; no additional answerer call, but ingestion cost is material.

## Datasets

StateMemBench: 234 scenarios and 322 probes; 190 shorter scenarios averaging 165 turns and 44 longer averaging 599 turns. Approximate token lengths are only 3K and 7–15K.

## Baselines

RAG, GraphRAG, memory systems and long-context controls under matched context variants.

## Metrics

Current-state accuracy, stale-state drift and other error classes.

## Main Findings

StateMem improves over RAG for one backbone (0.363 versus 0.205); a different backbone is close to GraphRAG (0.233 versus 0.224). Dynamic-state and dependent-memory management already have direct precedents.

## Ablations

Typed state/dependencies and length-matched context controls; Appendix H cost.

## What It Actually Solves

Track evolving current state and dependent constraints. The empirical support is restricted to the tasks and controls described above.

## What It Does NOT Solve

Dependency links are explicit; synthetic construction favors typed state. This is a scope assessment, not a claim that the approach could never be extended.

## Author-Stated Limitations

Synthetic scenarios, explicit dependency statements, limited backbones and single-run design.

## Additional Limitations We Observe

Many turns do not imply a million-token horizon. Full transcript plus retrieved state can be an advantage unless context is matched. Explicit linguistic dependencies simplify the unknown-lineage problem.

## Relationship to Other Papers

STALE/CUPMem, StateAuditor and dependency-guided rollback.

## Relevance to EvoMem
