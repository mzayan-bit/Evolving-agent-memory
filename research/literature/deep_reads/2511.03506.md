**HaluMem: Evaluating Hallucinations in Memory Systems of Agents**. Chen, Ding; Niu, Simin; Li, Kehang; Liu, Peng; Zheng, Xiangping; Tang, Bo; Li, Xinchi; Xiong, Feiyu; Li, Zhiyu. ## Research Problem

Measure memory hallucination during extraction, update and answering

## Why This Paper Exists

The design targets a concrete weakness in how prior agents evaluate or use memory. Measure memory hallucination during extraction, update and answering. Its scope matters because generative error scope deliberately excludes retrieval as a hallucination stage.

## Method

Annotate memory extraction, update and downstream QA, separating omissions, unsupported additions and corruption. Evaluate operation quality directly rather than attributing every answer error to retrieval.

## Memory Lifecycle Covered

- **Write:** Extraction integrity/accuracy probes
- **Retrieve:** Retrieval explicitly outside generative-hallucination attribution scope
- **Update:** Update probes
- **Consolidate:** Implicit through memory extraction/update evaluation
- **Invalidate:** Incorrect updates can be observed
- **Forget:** Deletion not a complete independent evaluation axis

## Representation

Operation-annotated memory histories

## Controller / Decision Policy

Stage-specific probes. API-heavy benchmark; top-10 update and top-20 QA retrieval settings appear in implementation details. Measure asynchronous completion rather than fixed sleep assumptions.

## Datasets

HaluMem medium/long conversation-derived settings with annotated memories and QA.

## Baselines

Mem0/graph, Memobase, MemOS, Supermemory and Zep under available APIs.

## Metrics

Integrity, accuracy, omission, hallucination and QA measures.

## Main Findings

Memory quality can fail before answer generation. It already provides direct evidence against the claim that only final recall accuracy is measured.

## Ablations

System, stage and context-length analyses; accessible API stages differ across backends.

## What It Actually Solves

Measure memory hallucination during extraction, update and answering. The empirical support is restricted to the tasks and controls described above.

## What It Does NOT Solve

Generative error scope deliberately excludes retrieval as a hallucination stage. This is a scope assessment, not a claim that the approach could never be extended.

## Author-Stated Limitations

API extraction availability and asynchronous update timing constrain fully uniform evaluation.

## Additional Limitations We Observe

Excluding retrieval as a source of generative hallucination is a scope choice, not evidence retrieval never causes wrong answers. Operation labels and judges can themselves err.

## Relationship to Other Papers

TRUSTMEM uses transition-quality feedback; MemFail and MemOps expand diagnosis.

## Relevance to EvoMem
